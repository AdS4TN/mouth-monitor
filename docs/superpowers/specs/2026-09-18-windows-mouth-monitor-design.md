# Windows 持续张嘴提醒工具设计

## 1. 目标

将现有 Python 视觉原型整理为一个能够在 Windows 电脑上实际使用、可放到 GitHub 发布的轻量本地工具。

用户主动启动程序后，可以在浏览器页面中查看摄像头画面、完成个人校准并开始监控。当系统检测到嘴唇持续未闭合达到设定时间时，页面突出提醒并播放 Windows 系统提示音。

本工具检测的是“持续张嘴或嘴唇未闭合”这一可观察状态，只能作为疑似口呼吸行为提醒，不能确认空气是否经过口腔，也不是医疗诊断工具。

## 2. 产品边界

### 包含

- Windows 本地运行。
- USB 或内置摄像头自动发现与选择。
- 本地 MediaPipe 人脸关键点推理。
- 闭嘴与轻微张嘴双点个人校准。
- 校准与用户设置本地持久化。
- 闭合、嘴部活动、张开候选、持续张开等状态判断。
- 页面视觉提醒和 Windows 系统提示音。
- 提醒冷却，避免连续播放。
- 启动、暂停、恢复、停止、重新校准和测试提醒。
- 源码运行、PyInstaller 打包和 GitHub Actions 构建。

### 不包含

- 鼻腔或口腔气流检测。
- 医疗诊断、治疗建议或准确率承诺。
- 麦克风、热成像或外接呼吸传感器。
- 云端账户、远程推理、数据同步或视频上传。
- 静默开机启动、Windows 服务或系统托盘常驻。
- macOS、Linux 和 Android 正式适配。
- 自定义视觉模型训练。

## 3. 用户流程

```text
双击 EXE 或运行命令
→ 启动本地服务
→ 自动打开浏览器页面
→ 自动扫描摄像头
→ 用户选择并启动摄像头
→ 已有有效校准则直接监控
→ 否则完成闭嘴和轻微张嘴校准
→ 开始监控
→ 持续张嘴达到阈值
→ 页面变红并播放系统提示音
→ 进入冷却期
→ 用户闭嘴后恢复正常状态
```

停止程序时必须释放摄像头和 MediaPipe 模型资源。

## 4. 技术方案

### 4.1 技术栈

- NumPy

- Pydantic
- PyInstaller
- pytest

### 4.2 运行形态

应用作为普通 Windows 用户进程运行：

```text
MouthMonitor.exe
├── FastAPI 本地服务：127.0.0.1
├── 摄像头与 MediaPipe 后台线程
├── JSON 配置存储
├── Windows 系统提示音
└── 默认浏览器调试与控制页面
```

应用不安装 Windows 服务，不要求管理员权限。浏览器关闭后后台进程仍然存在，但本版本不保证无界面长期运行；用户可以重新访问本地地址继续控制。

## 6. 摄像头设计

### 自动扫描

启动时扫描有限索引范围，例如 `0..5`：

- 尝试 DirectShow。
- DirectShow 失败时尝试 MSMF 或默认后端。
- 必须成功读取实际帧才认为摄像头可用。
- 向页面返回可用索引与显示名称；无法获得名称时显示“摄像头 0”等稳定名称。

扫描时不能长期占用设备，每次探测后立即释放。

### 运行配置

- 默认 `640×480`。
- 目标分析频率约 8～10 FPS。
- 一次只处理一张人脸。
- 不保存原始帧。
- 调试画面使用低质量 MJPEG，避免额外编码负载。

### 异常处理

区分以下状态：

- 未发现摄像头。
- 摄像头被其他应用占用。
- 成功打开但无法读取帧。
- 连续黑帧或过暗。
- MediaPipe 初始化失败。
- 未检测到人脸。

错误必须显示可执行的恢复建议，不把所有问题统一显示为“未检测到人脸”。

## 7. 视觉与特征设计

MediaPipe 输出 478 个人脸关键点。第一版继续使用四点几何特征：

- 上唇：13
- 下唇：14
- 左嘴角：78
- 右嘴角：308

计算：

```text
开合比例 = 上下唇欧氏距离 / 左右嘴角欧氏距离
```

使用比例而不是像素距离，以降低用户前后移动产生的尺度影响。

第一版保留四点方案，不加入模型训练。若关键点明显丢失或画面质量不足，输出“无法判断”而不是猜测。

## 8. 校准设计

### 流程

1. 自然、舒适地闭嘴并采集 3 秒。
2. 轻微张开嘴唇并采集 3 秒。
3. 对有效样本使用中位数生成两个参考值。
4. 生成进入张开阈值与恢复闭合阈值。

### 默认公式

```text
gap = open_baseline - closed_baseline
enter_threshold = closed_baseline + gap × 0.45
exit_threshold = closed_baseline + gap × 0.25
```

### 有效性检查

- 每一阶段必须获得最低数量的有效样本。
- 张嘴参考必须明显高于闭嘴基线。
- 采样期间波动过大则校准失败并要求重试。
- 校准记录包含配置版本与摄像头索引。
- 用户更换摄像头后提示重新校准，但允许手动继续使用旧数据。

## 9. 状态机

状态：

```text
STOPPED
NO_CAMERA
NO_FACE
NOT_CALIBRATED
CALIBRATING
CLOSED
MOUTH_ACTIVE
OPEN_CANDIDATE
SUSTAINED_OPEN
COOLDOWN
ERROR
```

判断顺序：

1. 摄像头或模型不可用时输出错误状态。
2. 没有人脸时输出 `NO_FACE` 并清除当前持续计时。
3. 校准期间只采样，不触发提醒。
4. 最近一秒嘴部运动标准差超过阈值时输出 `MOUTH_ACTIVE`。
5. 平滑比例超过进入阈值时进入 `OPEN_CANDIDATE` 并累计真实时间。
6. 达到持续时间后进入 `SUSTAINED_OPEN` 并请求提醒。
7. 提醒后进入 `COOLDOWN`，冷却期间不重复播放。
8. 比例低于退出阈值后回到 `CLOSED` 并清除计时。

持续时间必须使用单调时钟，不按帧数计算。

## 10. 提醒设计

### 默认行为

- 默认持续张开 8 秒后提醒。
- 页面状态区域变为醒目的红色。
- 使用 Python 标准库 `winsound` 播放 Windows 系统提示音。
- 默认冷却 30 秒。
- 冷却结束后如果仍持续张开，可以再次提醒。

### 用户设置

- 触发时间：3～30 秒。
- 冷却时间：10～300 秒。
- 提醒音开关。
- 嘴部活动灵敏度。
- “测试提醒”按钮。

如果 `winsound` 调用失败，只保留页面视觉提醒并记录非致命错误。

## 11. 本地存储

默认存储目录：

```text
%LOCALAPPDATA%\MouthMonitor\config.json
```

保存：

- 配置版本。
- 摄像头索引。
- 闭嘴基线与张嘴参考。
- 进入和退出阈值。
- 触发时间和冷却时间。
- 提醒开关和运动阈值。

不保存：

- 图片或视频。
- 完整面部关键点。
- 人脸身份信息。
- 历史监控记录。

配置使用临时文件加替换方式原子写入。损坏或版本不兼容时回退到默认配置并提示重新校准。

## 12. Web 接口

### HTTP

- `GET /`：主页面。
- `GET /api/state`：当前状态快照。
- `GET /api/cameras`：可用摄像头列表。
- `POST /api/camera/select`：选择摄像头。
- `POST /api/start`：开始监控。
- `POST /api/pause`：暂停并释放摄像头。
- `POST /api/stop`：停止并释放资源。
- `POST /api/calibrate/closed`：闭嘴校准。
- `POST /api/calibrate/open`：张嘴校准。
- `POST /api/settings`：保存设置。
- `POST /api/reminder/test`：测试提醒。
- `GET /video`：MJPEG 调试画面。

### WebSocket

- `WS /ws`：约每 100ms 推送状态快照。

本地服务只监听 `127.0.0.1`，不暴露到局域网。

## 13. 页面设计

保持工具型单页布局：

- 左侧：摄像头画面和嘴唇关键点。
- 右侧：当前状态、比例、阈值、持续时间、FPS 和推理耗时。
- 顶部：非医疗工具和隐私说明。
- 底部：摄像头选择、启动、暂停、停止、双点校准、重新校准、提醒测试和设置。

页面不是正式商业视觉稿，优先保证所有内部状态可观察和错误可定位。

## 14. 打包与 GitHub

### 本地运行

```powershell
uv sync
uv run mouth-monitor
```

### Windows 打包

提供 `scripts/build.ps1`：

1. 安装锁定依赖和 PyInstaller。
2. 将 MediaPipe 模型和网页资源作为数据文件打包。
3. 生成 `dist/MouthMonitor/MouthMonitor.exe` 目录式发布包。
4. 启动后自动定位打包资源。

优先使用 PyInstaller `onedir`，不采用 `onefile`，避免模型与动态库启动时反复解压造成慢启动和杀毒误报。

### GitHub Actions

Windows 工作流执行：

- 安装 uv。
- 同步依赖。
- 运行测试。
- 执行打包脚本。
- 上传 ZIP artifact。

### 仓库文件

- 根目录 `README.md`：功能、截图占位、运行、打包、隐私和限制。
- `LICENSE`：MIT。
- `.gitignore`：缓存、日志、配置、模型缓存和构建产物。
- `CONTRIBUTING.md`：最小开发说明。
- GitHub Actions 工作流。

本任务只整理本地 Git 仓库，不自动创建 GitHub 远程仓库或推送；远程操作需用户明确授权并提供目标。

## 15. 测试策略

### 自动测试

- 开合比例计算。
- 双点校准阈值生成。
- 校准失败条件。
- 状态机闭合、活动、持续张开和冷却路径。
- 配置保存、读取和损坏恢复。
- 提醒冷却与关闭提示音。
- FastAPI 关键控制接口。

### 人工验证

- 启动后自动打开浏览器。
- 摄像头选择和切换。
- 校准后重启仍保留。
- 闭嘴时保持正常。
- 持续张嘴后播放一次提醒。
- 正常说话时尽量进入嘴部活动状态。
- 停止后系统相机可以立即重新占用摄像头。
- 打包后的 EXE 在没有 Python 环境的 Windows 机器上运行。

## 16. 验收标准

1. 源码安装后可用一条命令启动。
2. 应用可发现并打开 USB 或内置摄像头。
3. 页面能够显示摄像头画面和四个嘴唇关键点。
4. 用户能够完成双点校准。
5. 校准和设置在应用重启后保留。
6. 持续张嘴达到阈值后页面变红并播放 Windows 提示音。
7. 冷却期内不会连续重复提醒。
8. 暂停或停止后摄像头被正确释放。
9. 自动测试通过。
10. PyInstaller 能生成可双击运行的 Windows 发布目录。
11. GitHub Actions 能生成 ZIP 构建产物。
12. README 明确说明隐私边界和非医疗定位。
