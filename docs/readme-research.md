# README 调研记录

调研日期：2026-09-18

本记录用于总结同类开源提醒工具和本地视觉工具如何介绍项目，并说明 Mouth Monitor README 的改写依据。

## 参考项目

### Open Posture

来源：https://github.com/whatnotbot/open-posture

- 开头先定义产品边界：基于个人校准比较姿态，而不是宣称存在唯一正确姿势。
- 用“个人化、克制提醒、隐私、无后端”解释为什么值得使用。
- 在安装之前提供首次使用流程、工作原理图和功能表。
- 将隐私承诺拆成可验证的技术行为，而不是只写“保护隐私”。
- 单独列出平台支持证据、限制和非医疗定位。

### Stretchly

来源：https://github.com/hovancik/stretchly

- 一句话说明它解决什么问题，然后描述默认行为。
- 具体解释提醒什么时候发生、用户能如何暂停或跳过。
- 把用户行为和实际产品体验放在配置参数之前。
- README 同时服务普通用户和开发者，但优先讲使用方式。

### Safe Eyes

来源：https://github.com/slgobinath/SafeEyes

- 使用清晰、直接的产品定位句。
- 提供多种安装方式和完整功能列表。
- 明确列出项目可扩展能力、开发检查和贡献入口。

### PosturePilot

来源：https://github.com/shoali2023/posture-pilot

- 将摄像头数据是否上传、首次联网下载什么资源、数据保存在哪里写得非常具体。
- 单独列出光线、角度、距离、多人画面和临床有效性等限制。
- 使用截图目录展示不同功能状态。

### Desk Health Web

来源：https://github.com/VeniVeci/desk-health-web

- 中文 README 直接说明摄像头处理位置和哪些数据会保存。
- 对健康相关功能明确区分“提醒记录”与“诊断治疗”。
- 路线图和贡献建议具体到可执行事项。

## 应用于 Mouth Monitor 的结论

1. 开头先描述目标用户、真实场景和产品边界。
2. 将“张嘴提醒”与“口呼吸诊断”明确分开。
3. 在安装命令之前解释个人校准和完整工作流程。
4. 用流程图、能力表和真实截图降低理解成本。
5. 将隐私承诺写成服务监听范围、数据生命周期和持久化内容。
6. 同时列出适用场景、不适用场景、已知限制和医疗免责声明。
7. 为技术读者解释关键点比例、滞回阈值和状态机设计。
8. 提供明确路线图和希望社区反馈的问题。
